## 1. The hard voice claim

**Bay Six stays consistent with what the technician actually heard, even when
they interrupt mid-sentence while a slow tool call is in flight.**

Concretely, when the technician barges in:

1. Queued Rime audio stops promptly, and audio Rime has accepted but not yet
   generated is cancelled at the source.
2. Audio belonging to the superseded turn can never reach the speaker, on either
   side of the socket.
3. The in-flight tool call is aborted, and a result that resolves late is never
   spoken as current.
4. The model's conversation history is rewritten to contain **only the words
   that reached the speaker**, marked as cut off.

Point 4 is the part that most interruptible agents get wrong, and it is the one
with the longest tail. An agent that records its full intended sentence in
history will, on the next turn, refer back to a part number the technician never
heard it finish saying. The bug is invisible on turn one and obvious on turn
three.

### Why this problem, for this user

A technician under a lift has no screen and no scrollback. The interface is
speech, entirely. That makes two things true at once: interruption is the
*normal* way they correct the agent ("no, the 2019"), and there is no visual
channel to repair a desync once it happens. Removing speech from Bay Six does
not degrade it — it deletes it.

## 2. Why Rime is load-bearing

This is not "an LLM with a play button". Two Rime `ws3` primitives are used
structurally, and removing either one would force a materially worse design:

| Rime primitive | What Bay Six does with it | What we would have to do without it |
| --- | --- | --- |
| `{"operation":"clear"}` | Cancels synthesis Rime has accepted but not yet emitted, so barge-in is authoritative end to end. | Drop audio locally while the server keeps generating and billing a response nobody will hear, and keep discarding its chunks as they arrive. |
| `contextId` on every chunk | Turns "is this chunk stale?" into an equality check against the live turn. | Guess from timing — a race that fails exactly when the network is slow, which is when barge-in matters most. |
| word timestamps (`type: "timestamps"`) | Converts `samplesPlayed` into *which words* were heard, which is what gets written to history. | Estimate linearly from byte counts, and mis-attribute the cut point on any sentence with uneven pacing. |

The delivery layer is Rime-shaped too: `server/ear.ts` rewrites every identifier
and spec into text meant to be heard once, and the commas it inserts are
rendered by `coda` as breath-length pauses — that is the mechanism that gives
the technician time to write `R C, eleven forty-seven, B` down.

## 3. Shipped configuration

Validated against Rime's **live** catalog by `npm run preflight`, not copied
from a doc page.

| field | value |
| --- | --- |
| model ID | `coda` |
| speaker | `astra` |
| language | `en` |
| audio format | `pcm` (s16le mono) |
| sampling rate | `24000` Hz |
| segmentation | `segment=immediate` |
| endpoint | `wss://users-ws.rime.ai/ws3` |
| transport | JSON WebSocket, persistent, server-side proxied |

**Format rationale.** `pcm` rather than a compressed format because the browser
must be able to stop mid-buffer and count exactly how many samples reached the
output device. A compressed stream would put a decoder between us and that
number, and the number is the evidence. The AudioContext is pinned to 24 kHz for
the same reason: no resample, so `samplesPlayed` is a count and not an estimate.

**`segment=immediate`** because Bay Six does its own clause segmentation
(`server/segmenter.ts`) and hands Rime complete clauses. Letting Rime wait for
sentence boundaries as well would add a second buffering stage to the number the
technician is waiting on.

**Transport rationale.** `ws3` rather than the HTTP endpoint because `clear` and
`contextId` exist only there. See the table in §2.

## 4. Acceptance tests

Written down before the demo was recorded. Thresholds live in `ACCEPTANCE` at
the top of `scripts/evidence.ts` and are echoed into every results file.

| id | claim | threshold |
| --- | --- | --- |
| **AT-1** | barge-in to silence, server-side stop path | p95 ≤ 150 ms |
| **AT-2** | audio from a superseded turn reaching the speaker | exactly 0 |
| **AT-3** | stale tool results spoken as current | exactly 0 |
| **AT-4** | history rows claiming more than was heard | exactly 0 |
| **AT-5** | mic frames accepted while speaking **and** while a tool runs | ≥ 1 each |
| **AT-6** | raw identifiers surviving into speech | exactly 0 |

### Procedure

```bash
npm run preflight              # validates the shipped config against the live catalog
npm run evidence               # AT-1..AT-6, n=20, needs RIME_API_KEY
npm run evidence -- --n 40     # more trials
npm run evidence -- --only AT-6   # the pure-function test, no key needed
npm run pronounce              # renders the before/after clips for §6
```

`scripts/evidence.ts` drives the **real** `VoiceSession` — the same turn state
machine, the same `ws3` socket, the same fencing rules, the same ledger — via a
headless client in `scripts/harness.ts`. Only the microphone and the loudspeaker
are simulated. The simulated speaker consumes audio in real time
(`samples / sampleRate` seconds per chunk), so `samplesPlayed` at the moment of a
barge-in is a faithful analogue of a real output device.

The tests default to the **deterministic scripted planner** rather than Claude.
That is on purpose: a measured stop latency should be a property of the audio
pipeline, not of a sampling temperature. Set `ANTHROPIC_API_KEY` to run the same
tests against the real planner.

### What AT-1 measures, precisely

Both timestamps come from the *client's* clock:

- **start** — the moment the user's voice crossed the VAD threshold, taken from
  the **first** loud audio quantum, not the one that finally convinced the
  detector. Reporting the later one would silently shave ~16 ms off every
  measurement.
- **end** — the moment the player confirms silence, plus
  `AudioContext.outputLatency`, because the last sample handed to the device is
  still in its buffer. This correction makes the reported number *worse*, which
  is the direction honesty runs in.

The client→server→client round trip is therefore **inside** the measurement, not
outside it.

## 5. Limitations — read this before quoting any number

- **The headless harness measures the server-side stop path.** Barge-in
  received → `stop_audio` ordered → simulated playback halted. A real browser
  adds one render quantum (5.33 ms at 24 kHz) plus `AudioContext.outputLatency`,
  which the on-screen HUD displays live per machine. The browser figure is the
  one a technician experiences; the harness figure is the one that is
  reproducible on any machine. **They are not the same number and are never
  presented as such.**
- **Cold vs warm.** The `ws3` socket is opened at session start and kept warm. A
  cold connection adds a TCP + TLS + auth handshake. Every trace row carries a
  `cold` flag; `npm run preflight` reports its own cold HTTP timing separately.
  Nothing in this repository averages a cold run into a warm one.
- **No caching anywhere.** Bay Six does not cache synthesised audio. Every
  measurement is an uncached render. There is consequently no cached/uncached
  split to report, and none is claimed.
- **Barge-in depends on acoustic echo cancellation.** The mic stays open while
  the speakers play, so without AEC the agent hears itself and interrupts
  itself. `getUserMedia` is requested with `echoCancellation: true`; on hardware
  without it, use a headset. This is a real dependency, not a footnote.
- **Speech recognition is the browser's Web Speech API.** Chosen so a judge can
  reproduce the demo with a Rime key alone. It is the weakest link in the chain
  for accented speech and shop noise, and it is not part of any claim made here.
  Bay Six owns turn-taking, orchestration, state and fencing; ASR is swappable.
- **AT-3's stale-result check is domain-specific.** It asserts that the 2018-only
  SKU never appears in the audio ledger of a turn the user cut off before the
  lookup finished. That is a strong signal, not a proof of the general property.
- **Sample sizes are small.** `n=20` by default. Treat single-run figures as
  exploratory; `--n 40` and up is cheap and preferred for any figure that gets
  quoted.
- **Not tested on telephony.** The audio format is configurable to `mulaw` for a
  phone transport, but no phone path has been measured, so no claim is made
  about one. Browser results do not prove telephone performance.
- **Fixtures are synthetic.** The parts catalog and torque specs are invented.
  They are shaped like real ones because their *pronunciation* is the point.

## 6. Pronunciation and controlled delivery (supporting claim)

`npm run pronounce` renders every fixture in `fixtures/pronunciation.json`
**twice** through the same model, speaker, language and sampling rate — the only
variable is the text:

- `evidence/clips/<id>.raw.wav` — the catalog string as written
- `evidence/clips/<id>.ear.wav` — the same string through `server/ear.ts`

and writes `evidence/pronunciation.md` naming both texts, the rules that fired,
and what to listen for. Nothing here is scored automatically. The claim is about
intelligibility on one hearing, and the only honest instrument for that is a
pair of clips and a human ear.

Representative rewrites (all verified by AT-6):

| written | spoken |
| --- | --- |
| `RC-1147-B` | R C, eleven forty-seven, B |
| `WP-40312-A` | W P, four, oh three, twelve, A |
| `39 Nm` | thirty-nine newton metres |
| `0W-20` | zero W twenty |
| `bin A14` | bin A fourteen |
| `2019 Civic 1.5T` | twenty nineteen Civic one point five turbo |

The commas are load-bearing, not cosmetic: `coda` renders them as short pauses,
which is what gives the technician time to write each group down before the next
one arrives.

## 7. Failure behaviour

| dependency fails | what happens |
| --- | --- |
| `RIME_API_KEY` missing or invalid | Session still starts. The HUD shows **RIME — NO KEY** and the log carries the exact error. No silent substitute provider is engaged. |
| Rime socket drops mid-turn | The turn closes with whatever played; the socket reconnects lazily on the next turn. History records only what was heard. |
| `ANTHROPIC_API_KEY` missing | The deterministic scripted planner runs. The HUD says `scripted (no ANTHROPIC_API_KEY)`. |
| Anthropic rate limit / API error | A short spoken apology, turn closes cleanly, history stays consistent. |
| Microphone denied, absent, or the permission prompt is ignored | Session starts anyway on typed turns. The **Interrupt** button sends the identical `barge_in` message, so the stop path is still exercised and still measured. |
| Web Speech API unavailable | Logged; typed turns continue to work. |

There is **no fallback TTS provider**. Rime is the only path to audio, so there
is nothing that could quietly take over and make a Rime failure look like
success.
